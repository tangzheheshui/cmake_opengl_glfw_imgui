# RHI 接口契约

RHI 是引擎内部统一两个后端的图形接口层。这份写它有哪些东西、保证什么、不保证什么。

## 有哪些东西

| 东西 | 类名 | 干什么 |
|---|---|---|
| 工厂 | RHIFactory | 按后端创建设备（入口） |
| 设备 | IRHIDevice | 创建、销毁资源；开始一帧、结束一帧 |
| 命令列表 | IRHICommandList | 录一帧的绘制命令 |
| 缓冲 | BufferHandle | 顶点、索引等数据 |
| 纹理 | TextureHandle | 贴图 |
| 采样器 | SamplerHandle | 贴图怎么采样 |
| 管线 | PipelineHandle | 着色器加渲染状态，创建时一次定死 |
| 离屏目标 | RenderTargetHandle | 渲染到纹理而不是屏幕 |
| 数据块 | UniformBlockHandle | 每帧每个对象传的小数据（只记尺寸，不占显存） |

## 保证什么

- 一帧的命令，在「结束一帧」后才真正交给 GPU 执行。
- 开始一帧如果失败（窗口重建中），会返回 false，上层跳过这一帧。
- 销毁对象后句柄失效，再用会报错，不是静默出错。

## 不保证什么（上层不能依赖）

| 项 | 说明 |
|---|---|
| 参数怎么传 | OpenGL 按名字，Vulkan 按固定位置，上层只管传值 |
| 颜色空间细节 | 两端都用 sRGB，但内部实现不同 |
| 回读行序 | OpenGL 第一行是画面底部，Vulkan 第一行是画面顶部 |
| 文字渲染 | 目前只有 OpenGL 支持 |

## 销毁顺序（硬规定）

1. 图形设备必须在窗口销毁之前销毁。
2. 帧还在 GPU 飞时，销毁请求先登记，帧末才真正销毁。
3. 顺序错了会崩（Vulkan 尤其严格）。
