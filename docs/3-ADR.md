# ADR（架构决策记录）

这份记「为什么这么决定」。每条一行，写清楚决定和理由。

| 决定 | 理由 |
|---|---|
| 资源用句柄表示，不用对象类 | 图形资源的生死由 GPU 控制，和 C++ 对象的生命周期不一致；句柄简单、能复制、好查错 |
| 设备默认由引擎创建并销毁，宿主也可注入现成设备 | app 层不该认识 `RHIFactory`/设备生命周期；引擎自建自毁让宿主只管窗口。需要多软件共享一个设备时，宿主仍可注入设备（引擎只借用不销毁） |
| 引擎不读后端环境变量 | 选哪个后端是宿主的事，引擎不该看环境 |
| 出错返回错误码，不抛异常 | 做成库，给别的软件用时更好处理错误 |
| OpenGL 上下文由宿主创建 | 引擎不拥有窗口，不依赖窗口库 |
| 公共类放进命名空间 | 避免和宿主的 Scene、Model、Camera 撞名字 |
| 销毁延迟到帧末 | 帧还在 GPU 飞的时候，不能立刻删资源 |
| 纹理自带描述符集，绘制数据走帧内环 | 每个网格各建一套 UBO 加描述符集，开销随网格数上涨，还会互相污染；改成纹理建一次、数据顺序追加，绘制期零描述符更新 |
| 两帧在飞，每帧一套命令缓冲和同步 | 单帧时 CPU 录完要等 GPU 画完才能录下一帧；两帧在飞让录制和绘制重叠，代价是多一套 uniform 环（每帧槽位 1MB）和延迟销毁多等一帧 |
| 不做 bindless、光追、HDR 等 | CAD 用不上，而且 OpenGL 必须能回退 |
| 业务层只留一条 RHI 路径，删光 GL 遗留代码 | 双路径切换开关看似保险，实际是两套代码两份 bug；一致性靠整帧逐像素对比兜底，比养两条路径便宜 |
| GL 的 sRGB/深度语义差异收进 Pass 边界 | 业务层写「默认编码、UI 关编码」就够了，不该知道 GL_FRAMEBUFFER_SRGB 存在；纯深度 Pass 转 Reversed-Z 让阴影两端共用一套比较逻辑 |
| 不做独立传输队列 | mip blit 要 GRAPHICS 队列、屏障等到 FRAGMENT 阶段专队列不支持、跨队列同步复杂易挂设备；上传已批处理收益没了（详见 docs/7「评估后不做」） |
| 接口先冻结再开发 | 多人并行时不互相撞公共头文件 |
